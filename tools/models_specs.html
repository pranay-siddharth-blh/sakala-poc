Sakala Mitra: Models and Specs

26 Oct 2026 · Thulasi Ram with Claude · replaces the 19 Oct 2026 edition · source of truth: Mitra_RD_Handoff.md section 3 and the code (mitra/server/config.py, live.py, brain.py, speech.py, main.py, app/server/ai.py, docread.py, local_ai.py)

Sakala Mitra runs on Google Gemini only, since 23 Oct 2026: one live voice model for full-duplex conversation in English and Kannada, Gemini text and speech models for the step-by-step (cascade) path, and Gemini text models for every AI job inside the Sakala POC. The office H200 gateway (Qwen) is no longer called by anything. The browser's own speech engines, a rules brain and an offline classifier remain as fallbacks that need no network. No model ever produces a number on screen: every figure comes from SQL on the POC database.

What changed since the 19 Oct edition. The gateway models (rows 9 to 11 then) are removed. The POC's understanding, petition reading, ATR draft and check, AI mode and officer-message translation moved from qwen4-deploy to gemini-3.6-flash through Gemini's OpenAI-compatible endpoint. 1 · Gemini Live: the conversation model

gemini-3.8-live carries every conversation on all three desks (Citizen, Officer, Chief Secretary), in English and in Kannada. It listens, understands, calls Mitra's functions and speaks the answer in one streaming session, so the person can interrupt at any time.

Published specs (Google model page)

SpecValue

How Mitra uses it (mitra/server/live.py)

  • Transport: browser ⇄ Mitra server (/ws/live) ⇄ Gemini Live WebSocket. The API key never reaches the browser.
  • Audio: 16 kHz 16-bit mono PCM in, 24 kHz PCM out. Prebuilt voice Kore, temperature 0.6.
  • Turn-taking: Google's voice activity detection, 700 ms of silence ends a turn, 200 ms prefix padding. Input and output transcription on: they drive the captions, the charts that build as Mitra speaks, and the number checks.
  • Setup per session: a system instruction for the profile (the Kannada persona block first on a Kannada session; function arguments stay in English), the screen context, the last 6 turns, and the function list for that profile: every cascade intent plus the ten data functions (case_info, find_cases, ipgrs_records, officer_profile, place_info, statewide_stats, sakala_2025, compare, ranking, dashboard). Kannada sessions set speechConfig.languageCode kn-IN.
  • Function calls run the same code as the cascade (tools.execute / query.run), so routing, permissions, notifications and real-time sync are identical on both paths. Gemini closes the tool-call turn before speaking the answer in the next one; the relay holds the exchange open. If nothing is said 4 s after a result the relay prompts once. If a data question ends with no function call, the server runs the deterministic router itself and pushes the picture.
  • Harness rules on the server hold whatever the model does: a language switch asked in either language is applied at the end of the turn; a Kannada or English 'submit' on an open form files it even if no function was called; the relay reads the result itself.
  • Guardrails on its output: function results sanitised and wrapped as data; vendor names scrubbed from captions; spoken numbers and ids checked against the function results, deviations logged; long Sakala numbers spoken as 'the application ending in 4811'.
  • Cost control: the session opens only on the wake word, an orb tap or typing, and closes after 20 s of silence.
  • Failure: on quota, network or model errors the browser uses the cascade for 5 minutes and the server marks Live down for 120 s.

Measured: session setup 1.3 s, first audio 0.45 s (Kannada about 0.5 s), function call 0.4 s, question to chart about 3 s. Real-Live batteries: English 32/32 and 11/11, Kannada live UI 18/18, language switching 8/8, document by voice 8/8, return with a suggestion 4/4.

2 · Gemini text and speech models: the cascade

The cascade handles typed input, the wake-word scanner, the first turn after a language switch, and every turn when Live is unavailable. It runs hear → decide → act → speak with one model chain per job. All calls go to models/{model}:generateContent. A 429 skips that model for 30 minutes, a 503 for 2 minutes, a 404 for good; when a whole chain is out the next engine in the row takes over. An English cascade turn takes 4 to 6 s end to end.

3 · Models inside the Sakala POC that Mitra calls

Mitra does not classify complaints itself. When a citizen speaks a complaint, Mitra sends the masked words to the POC (POST /api/intake) and the POC's own pipeline picks the service and the officer. These models run behind Mitra on every filing, and behind the WhatsApp channel alike. Configuration: POC_GEMINI_CHAIN and POC_GEMINI_STT_CHAIN in app/.env (defaults shown).

Error handling (ai.chat): a 429 or 5xx, a read timeout or a dropped connection moves to the next model of the chain; no network backs off for 60 s and the offline classifier answers. Every call is logged to ai_log. API behaviours found: the OpenAI-compatible endpoint supports json_schema with enums and additionalProperties:false, integer enums, vision image_url and reasoning_effort; it rejects chat_template_kwargs; an open {"type":"object"} comes back as {}, so every argument schema is declared in full.

Measured end to end (Gemini 3.6 Flash + router, 40 real Mysuru complaints, text only, 24 Oct): department 97.5%, service 72.5%, exact officer 77.5%; about 2.9 s per understanding call. The officer router is rules learned from the data, not a model: it matches the real iPGRS officer in 97.6% of 673 Mysuru cases and 95.7% of 4,611 statewide.

4 · The written-complaint reader (app/server/docread.py)

A handwritten or typed letter (PDF, PNG, JPG; Kannada, English or mixed) is read into the official iPGRS form and then goes through the same pipeline. Added 19 to 21 Oct; not in the previous edition.

StepModelsHow
Orientationgemini-3.1-flash-lite and gemini-3.6-flash, two voters in parallelThe four turns of the page on one labelled 2×2 sheet; 'which panel reads upright' with an A/B/C/D enum schema; the stronger model decides a tie. 12/12 on the gold letters at every rotation, about 3 s. PDFs skip it; a portrait photo is read at once with the check beside it.

A field is confirmed only when both extractions agree; a date far from today loses to the plausible reading. Thinking on, 90 s timeout each. 17/17 gold fields at about 6 s.
Fallback chain for any callGEMINI_MODEL (gemini-3.8-flash) then GEMINI_FALLBACK_MODELA lite model never thinks. The office gateway fallback was removed.
Retrieval anchornone (SQL)A 6-digit iPGRS number in the letter is looked up in the 9,999 real records and handed to understanding as strong evidence; its place fills a place the letter does not name.

Measured: 12 to 17 s from upload to the filled form with the officer preview on the three real handwritten letters (every field right, all three iPGRS numbers found); a repeat upload is instant by file hash. Accuracy was chosen over speed.

7 · Browser speech: the last resort

Speech recognition (Web Speech API, webkitSpeechRecognition): a fast path for the wake word when its cloud service is reachable. Edge sends audio to Microsoft, Chrome and Brave to Google. On the office VPN that service is blocked, so Mitra switches it off and relies on the server-side scanner. Speech synthesis (speechSynthesis): the operating system's voices read Mitra's reply when every voice model has failed. Mitra does not choose or configure the model behind either.

9 · Keys, cost and open items

  • Gemini: one API key from a prepaid Google AI Studio project, held on the server only (app/.env and mitra/.env on the laptop; /opt/sakala/app/.env, mode 600, on the server). Live is billed on audio tokens in and out, so sessions close after 20 s idle. The prepaid credits ran out once (17 Oct) and Mitra fell back cleanly until the top-up.
  • Configuration keys: GEMINI_API_KEY, GEMINI_MODEL, GEMINI_FALLBACK_MODEL, GEMINI_TTS_MODEL, GEMINI_VOICE, GEMINI_LIVE_MODEL; optional POC_GEMINI_CHAIN, POC_GEMINI_STT_CHAIN, GEMINI_BRAIN_CHAIN, GEMINI_STT_CHAIN, GEMINI_TTS_CHAIN; MITRA_BRAIN / MITRA_STT / MITRA_TTS (auto, gemini, rules or browser).
  • Network: outbound HTTPS and WSS to generativelanguage.googleapis.com and nothing else. No GPU anywhere; both services run on a 1 GB server.
  • Sarvam: no key; its models are never called.
